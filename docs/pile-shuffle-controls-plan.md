# 固定牌堆一键洗牌与整叠移动计划

> 适用分支：`feature/library-and-deckbuilding-table`  
> 适用阶段：主桌与备牌托盘固定牌堆交互优化  
> 项目原则：弱规则、弱状态、强同步、强可见性控制。  
> 本计划只处理固定牌堆的统一背面化、顺序随机化，以及整叠牌的移动说明；不增加规则自动化，不修改 VirtualTabletop 核心。

## 1. 背景与目标

当前项目已经存在：

- 主桌摸牌堆 `draw-pile`；
- 备牌托盘武将槽 `general-reserve`；
- 备牌托盘身份槽 `identity-reserve`；
- 备牌托盘扩展槽 `extra-reserve`；
- 备牌托盘血量槽 `marker-reserve`；
- 通用快捷洗牌区 `quick-shuffle-zone`；
- 快捷洗牌按钮及对应 Routine。

现有快捷洗牌区适合处理玩家临时选出的散牌或临时牌组，但对于上述五个长期固定牌堆，要求玩家先移动整叠牌、洗牌、再放回原槽，会增加操作步骤和误混牌风险。

本计划目标是：

1. 在五个固定牌堆附近提供专属“一键洗牌”按钮；
2. 每个按钮只作用于对应 Holder；
3. 每次操作只执行两个动作：全部背面朝上、随机打乱顺序；
4. 保留现有快捷洗牌区，用于临时牌组；
5. 不开发新的右键菜单，不修改原生右键放大；
6. 整叠牌移动继续使用 VirtualTabletop 原生 Pile 数量把手。

## 2. 最终方案

### 2.1 正式采用方案一

为以下五个固定牌堆分别添加独立按钮：

| 牌堆 | Holder ID | 按钮建议 ID |
| --- | --- | --- |
| 摸牌堆 | `draw-pile` | `shuffle-draw-pile-btn` |
| 武将牌堆 | `general-reserve` | `shuffle-general-reserve-btn` |
| 身份牌堆 | `identity-reserve` | `shuffle-identity-reserve-btn` |
| 扩展牌堆 | `extra-reserve` | `shuffle-extra-reserve-btn` |
| 血量牌堆 | `marker-reserve` | `shuffle-marker-reserve-btn` |

按钮显示文字统一建议为：

```text
🔀 洗牌
```

按钮必须与对应牌堆在视觉上直接关联，避免用户误判作用范围。

### 2.2 不开发新的右键方案

不新增 `contextMenuRoutine`，不修改 VirtualTabletop 客户端的 `contextmenu` 事件。

理由：

- 当前右键已经用于原生放大；
- `.vtt` Widget 没有可直接配置的右键 Routine；
- 修改右键需要维护自定义 VirtualTabletop 分支；
- 原生 Pile 已有数量把手，可以移动整叠牌；
- 右键整叠选择不能减少后续“拖到洗牌区、洗牌、拖回”的操作步骤；
- 对固定牌堆而言，专属按钮更直接、更安全。

## 3. 严格行为定义

每个专属洗牌按钮只允许执行：

```text
1. 将目标 Holder 中的全部卡牌统一设置为背面；
2. 对该 Holder 中的卡牌顺序执行真随机洗牌。
```

建议固定执行顺序：

```text
FLIP face 0
→
SHUFFLE true random
```

### 3.1 明确禁止的附加行为

专属洗牌按钮不得：

- 从其他区域收集卡牌；
- 将回收区卡牌移入摸牌堆；
- 将快捷洗牌区卡牌移入固定牌堆；
- 将任何牌移动到其他 Holder；
- 合并两个不同牌堆；
- 拆分牌堆；
- 调整牌堆坐标；
- 改变单张卡牌的旋转角度；
- 重置牌堆来源；
- 自动发牌；
- 自动抽牌；
- 自动判断身份、武将或扩展牌数量；
- 弹出确认框；
- 弹出“洗牌完成”提示；
- 修改布局锁定状态。

### 3.2 空牌堆与单张牌

空 Holder：

- 点击后无操作；
- 不报错；
- 不创建空 Pile；
- 不弹出提示。

只有一张牌：

- 将该牌设置为背面；
- 洗牌步骤允许自然无变化；
- 不报错。

### 3.3 已经背面的牌

无论目标牌当前是：

- 全部背面；
- 全部正面；
- 正反混合；

执行后都必须统一为背面，并完成随机排序。

## 4. Routine 设计

建议在 `src/routines/pileShuffle.ts` 中建立统一工厂，而不是为五个按钮手写重复数组。

参考结构：

```ts
export const createPileShuffleRoutine = (holderId: string) => [
  {
    func: 'FLIP',
    holder: [holderId],
    face: 0,
  },
  {
    func: 'SHUFFLE',
    holder: [holderId],
    mode: 'true random',
  },
] as const;

export const shuffleDrawPileRoutine = createPileShuffleRoutine('draw-pile');
export const shuffleGeneralReserveRoutine = createPileShuffleRoutine('general-reserve');
export const shuffleIdentityReserveRoutine = createPileShuffleRoutine('identity-reserve');
export const shuffleExtraReserveRoutine = createPileShuffleRoutine('extra-reserve');
export const shuffleMarkerReserveRoutine = createPileShuffleRoutine('marker-reserve');
```

### 4.1 与现有快捷洗牌 Routine 的关系

当前 `quickShuffleRoutine` 仍保留，但建议改为复用同一工厂或至少复用同一底层动作定义。

快捷洗牌区可以继续保留现有完成提示，也可以后续统一精简；本计划不强制修改其用户反馈行为。

专属固定牌堆按钮则必须严格无提示，只执行两个牌务动作。

### 4.2 不复用 `collectAndShuffleRoutine`

不得复用当前“收拢并洗牌”逻辑，因为该 Routine 包含从回收区移动卡牌到摸牌堆的行为，超出了专属按钮职责。

应确保代码层面明确区分：

```text
collectAndShuffleRoutine
= 收集回收区 + 洗摸牌堆

shuffleDrawPileRoutine
= 只洗现有摸牌堆
```

## 5. UI 布局

## 5.1 备牌托盘按钮

现有托盘保持：

```text
尺寸：520 × 220
槽位：武将／身份／扩展／血量
```

不扩大托盘，不移动四个牌槽，不增加页签。

在每个牌槽正下方添加小型按钮：

```text
┌─ 备牌托盘｜不参与常规洗牌 ─────────────┐
│  武将       身份       扩展       血量   │
│ [牌堆]     [牌堆]     [牌堆]     [牌堆] │
│ [🔀洗牌]   [🔀洗牌]   [🔀洗牌]   [🔀洗牌]│
└───────────────────────────────────────┘
```

建议按钮参数：

| 按钮 | x | y | width | height |
| --- | ---: | ---: | ---: | ---: |
| 武将 | 18 | 190 左右 | 100 | 24–26 |
| 身份 | 140 | 190 左右 | 100 | 24–26 |
| 扩展 | 262 | 190 左右 | 100 | 24–26 |
| 血量 | 384 | 190 左右 | 118 | 24–26 |

最终 y 坐标需根据实测确认，要求：

- 不遮挡牌堆；
- 不超出托盘边界；
- 托盘缩放时按钮与牌堆同步；
- 四个按钮之间不重叠；
- 文本在 75%、90%、100%缩放下仍可读。

### 5.2 摸牌堆按钮

在 `draw-pile` 正下方添加独立按钮：

```text
🎴 摸牌堆
[牌堆]
[🔀 一键洗牌]
```

按钮必须与现有：

- 快捷洗牌区；
- 快捷洗牌区按钮；
- 待回收区；

保持清晰间距，避免用户误认为该按钮会收集回收区或处理快捷洗牌区。

推荐文字：

```text
🔀 洗摸牌堆
```

或统一使用：

```text
🔀 洗牌
```

首选统一短文案，但应通过位置确保作用范围清晰。

## 6. 权限设计

首版建议：专属洗牌按钮仅玩家 1 可见和可操作，与当前房主工具逻辑保持一致。

理由：

- 身份、武将和摸牌堆属于关键公共牌堆；
- 按钮无确认框，误触会立刻改变顺序；
- 限制按钮权限不影响玩家手动移动、抽取和翻牌；
- 可以降低多人同时点击导致的重复洗牌和争议。

建议属性：

```ts
onlyVisibleForSeat: ['seat-1'],
linkedToSeat: ['seat-1'],
```

备选开放模式可在后续设置中加入，但不作为首版范围。

## 7. 与布局锁定的关系

布局锁定只控制可移动组件的位置，不应禁止洗牌按钮。

因此：

```text
布局锁定
→ 托盘不能移动
→ 洗牌按钮仍可使用
```

按钮本身始终：

```ts
movable: false
```

托盘缩放、移动或自动整理时，托盘内四个按钮作为子组件跟随根节点。

## 8. 通用快捷洗牌区的保留职责

现有快捷洗牌区继续保留，用于：

- 临时选出的若干张牌；
- 公共桌面上的散牌；
- 临时自定义牌组；
- 不属于五个固定 Holder 的牌；
- 玩家希望暂时形成并打乱的一组牌。

快捷洗牌区不得自动判断牌的原始来源，也不得自动将洗好的牌送回原 Holder。

固定牌堆不再要求通过快捷洗牌区完成常规洗牌，但玩家仍可手动这样操作。

## 9. 整叠牌移动说明

VirtualTabletop 原生 Pile 已提供带数量的把手。

正式交互说明应写为：

```text
拖动牌堆上的数量把手，可以移动整个牌堆。
```

该能力用于：

- 把临时整叠牌移入快捷洗牌区；
- 把整叠牌移动到其他公共区域；
- 人工整理桌面。

本项目不新增：

- 右键选取整叠牌；
- 右键拖动模式；
- 右键牌堆菜单；
- 自定义 Pile 句柄；
- 平台级上下文菜单。

## 10. 原生 Pile 菜单的边界

原生 Pile 点击菜单已有：

- 翻转整叠；
- 洗牌；
- 拆分；
- 关闭。

但原生“翻转整叠”是逐张切换正反面，不等价于“强制全部背面”。

因此专属按钮仍有必要：

```text
原生翻转：正面变背面，背面变正面

项目专属洗牌：无论当前朝向，全部设为背面，再随机打乱
```

## 14. 最终验收标准

只有同时满足以下条件，功能才算完成：

1. 备牌托盘四个固定牌堆均有独立洗牌按钮；
2. 摸牌堆有独立洗牌按钮；
3. 每个按钮只处理自己的 Holder；
4. 每个按钮只执行统一背面化和真随机排序；
5. 不自动移动、收集、合并或拆分卡牌；
6. 不弹确认框和完成提示；
7. 空牌堆和单张牌不会报错；
8. 托盘尺寸、槽位和现有视觉布局保持不变；
9. 快捷洗牌区继续可用于临时牌组；
10. 原生 Pile 数量把手继续用于整叠移动；
11. 不新增右键菜单；
12. 不修改 VirtualTabletop 核心；
13. 其他固定牌堆、玩家手牌、私密区和备牌面板不受错误影响；
14. 多客户端同步测试通过；
15. 牌的数量、ID、parent和所属牌堆在洗牌前后保持正确。

## 15. 冻结结论

本功能最终采用：

> **固定牌堆专属一键洗牌按钮＋现有通用快捷洗牌区＋原生Pile数量把手。**

不采用：

> **新增右键整叠选取或自定义右键菜单。**

固定牌堆按钮解决常规高频洗牌；快捷洗牌区继续处理临时牌组；原生数量把手负责整叠移动。三者职责清晰，且保持普通 `.vtt` 与原生 VirtualTabletop 完全兼容。

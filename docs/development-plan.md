## Phase 1.1：共享桌面重构、个人手牌、真实牌堆与视觉清晰化（实现完成，等待多会话人工验收）

### 1. 总体布局基线

下一版以最新布局示意图为正式基线，桌面分为五个层级：

1. **顶部功能控制条**：放置少量通用桌面操作。
2. **共享桌面上的玩家模块**：每个模块只包含对外展示区和私密展示区。
3. **中央牌务区**：摸牌堆与待回收／待洗牌区彼此独立。
4. **普通公共桌面**：无大边框、可自由放牌、不自动参与洗牌。
5. **个人手牌区**：独立于共享桌面，优先固定在每位玩家自己的视角底部。

桌面边缘允许放置一个或多个可移动、可锁定的备牌托盘。当前仍只制作 4 人原型，但布局结构不得阻碍后续增加或重新排列玩家模块。

### 2. 玩家结构：共享桌面只保留两个区域

废止“武将、体力、装备、判定、附加牌”五类固定槽位，不再使用大型玩家父模块包裹全部游戏内容。共享桌面上的每位玩家只保留：

1. **对外展示区**：武将牌、体力牌或标记、装备、判定、附加牌、公开身份及其他公开状态。
2. **私密展示区**：身份牌、暗置武将、私密任务牌及其他长期私密信息。

Seat、玩家名称和模块拖动把手放在模块标题栏中。建议标题栏包含：

```text
☰ 玩家名称    🔒/🔓
```

要求：

- 玩家模块可以整体移动和锁定。
- 对外展示区和私密展示区在模块内部保持清楚分隔。
- 卡牌操作区不能同时充当模块拖动区域，防止拖牌时误移动整个模块。
- 后续可增加“收起／展开模块”，但首版不以此为验收前提。
- 移动模块不得改变 Seat、卡牌所有者或私密可见性。

### 3. 私密展示区的隐私语义

私密展示区采用“物件存在公开、牌面内容私密”的模式：

- 卡牌进入私密展示区时默认恢复为背面。
- 所属玩家可以在区内翻面并查看真实正面。
- 其他玩家、观察者以及房主无论卡牌实际正反状态如何，始终只能看到牌背。
- 原生 `enlarge` 放大不得绕过遮罩；非所属玩家放大时仍只能看到牌背。
- 卡牌离开私密展示区时，必须在私密保护仍有效的情况下先恢复为背面，再解除该区域的私密归属。
- 卡牌移入普通公共桌面或对外展示区后继续保持背面。
- 只有玩家在公共区域再次手动翻面，其他人才可看到正面。
- 禁止“离开私密区即自动公开正面”，也禁止先解除隐私再翻回背面造成瞬时泄漏。

身份公开的标准操作为：

```text
私密展示区取出身份牌
→ 公共桌面或对外展示区中仍保持背面
→ 玩家手动翻面
→ 全体可见
```

### 4. 对外展示区的自由摆放

对外展示区是公开状态空间，不再细分武将槽、体力槽、装备槽、判定槽或附加牌槽：

- 玩家可以自由摆放武将、体力、装备、判定、附加牌和公开标记。
- 区域不自动识别或校验卡牌类别。
- 卡牌不会被强制排成固定队列。
- 两张或多张卡牌可以按玩家意图重叠、堆叠或错位摆放。
- 区域本身不自动翻牌，也不改变任何规则状态。
- 区域应使用低干扰半透明底板，公开属性通过标题和图标明确表达。

### 5. 个人手牌区

手牌区不再占用共享桌面四周的大块空间，优先实现为每位玩家自己视角底部的横向区域：

- 本人看到自己的手牌正面。
- 其他玩家和观察者默认只看到手牌数量，不显示真实手牌排列。
- 使用 `childrenPerOwner` 或等效原生归属机制。
- 手牌横向展开，手牌增加时自动压缩间距。
- 进入手牌区时建立本座位玩家归属。
- 玩家离座、换座和异常清理不得把原手牌错误转交给新玩家。
- `enlarge` 只能让所属玩家看到手牌正面，其他玩家不能利用放大功能绕过隐私。

#### 5.1 技术可行性门槛

优先验证 VirtualTabletop 游戏 JSON 是否可以让手牌区稳定固定在每个客户端的视口底部，而不是跟随共享桌面的世界坐标。

若原生 `.vtt` 无法可靠实现视口固定，不修改上游源码，采用降级方案：

- 在桌面底部保留一个统一的个人手牌条。
- 通过 `childrenPerOwner` 使每个客户端只在同一位置看到自己的手牌。
- 其他玩家仍只在其玩家模块或手牌数量标签上看到数量。

不允许为了实现固定底栏而注入不受支持的外部脚本或修改 VirtualTabletop 核心源码。

### 6. 查看他人手牌背面：临时盲选机制

“顺手牵羊”等场景需要从目标玩家手牌中随机或指定选择一张，但不能因此公开正面。不得直接解除真实手牌 Holder 的隐私。

推荐增加临时盲选机制：

1. 目标玩家或允许的操作按钮开启“展示手牌背面”。
2. 桌面临时显示与目标手牌数量一致的背面牌位或背面代理牌。
3. 所有非所属玩家只看到统一牌背，`enlarge` 也只能显示牌背。
4. 操作者选择一个位置。
5. 由安全映射 Routine 或目标玩家人工交出对应真实手牌。
6. 关闭临时盲选区并清理代理对象。

首版可以采用弱规则人工版本：操作者指出背面位置，由目标玩家手动交出对应牌。只有在不会泄漏牌面、不会改变真实手牌归属、不会复制真实卡牌的前提下，才实现自动映射。

建议使用明确按钮：

```text
展示手牌背面
收起手牌背面
```

不能把该操作绑定到普通手牌数量标签的单击事件，防止误触。

### 7. 中央牌务区

#### 7.1 摸牌堆

摸牌堆使用真正的 `pileZone`，初始牌应在同一坐标重叠并形成 VirtualTabletop 原生 Pile：

```ts
alignChildren: true
preventPiles: false
stackOffsetX: 0
stackOffsetY: 0
```

摸牌堆区域尺寸接近一张牌，显示清楚的名称和可选数量提示。不得通过横向散开表达牌数。

#### 7.2 待回收／待洗牌区

待回收区与摸牌堆必须并列，不得视觉重叠，也不得建立嵌套 Holder 父子关系。

- 玩家主动把需要重新进入牌堆的牌放入待回收区。
- 待回收区内可以自由摆放或暂存多叠牌。
- 点击“收拢并洗牌”后，只收集该区域内的牌。
- 洗牌完成后，将结果移入摸牌堆。
- 普通桌面、玩家展示区和备牌区中的牌不得被该操作自动回收。

建议正式名称使用“待回收／待洗牌区”，避免误解为任何弃牌都会自动参与洗牌。

### 8. 普通公共桌面

除明确标记的功能区域外，其余桌布均为普通公共桌面：

- 卡牌可以自由放置、重叠、翻面、旋转和形成 Pile。
- 不自动归类，不自动回收，不自动参与洗牌。
- 不使用覆盖大部分桌面的明显矩形边框。
- 可以保留非常淡的“公共桌面”文字或装饰纹理，但不得干扰卡牌识别。

普通公共桌面本身不是 Holder；卡牌离开功能 Holder 后可以作为普通桌面物件自由操作。

### 9. 备牌托盘

桌面边缘允许放置一个或多个可移动备牌托盘，用于：

- 扩展牌包；
- 备用身份；
- 备用武将；
- 特殊标记；
- 当前牌局未启用的内容；
- 临时规则需要的备用物件。

每个托盘可以包含多个真正支持 Pile 的槽位。要求：

- 牌槽允许卡牌真正重叠。
- 不参与摸牌堆洗牌。
- 不参与待回收区的洗牌。
- 常规“收拢并洗牌”不得清空备牌区。
- 只有明确的“完整恢复初始桌面”操作可以处理备牌托盘。
- 托盘整体可以移动和锁定。

正式视觉采用暗红、铜色或木质收纳风格，不使用高亮纯红大块底色。

### 10. 顶部功能控制条

顶部中央设置紧凑功能控制条。首版只保留通用桌面操作：

- 锁定／解锁布局；
- 自动整理；
- 收拢并洗牌；
- 整桌重置；
- 后续可加入显示／隐藏预设玩家模块和备牌托盘。

要求：

- 不把所有功能做成占据大量桌面的独立大按钮。
- 危险操作如整桌重置必须二次确认。
- 洗牌只处理待回收区。
- 房主专属操作与普通玩家操作应有视觉区别。
- 当前 4 人原型不要求运行时无限新增 Seat；可以先通过显示／隐藏预设模块验证布局。

### 11. Holder 按用途拆分

删除当前“一种 `zone()` 适用于全部区域”的设计，至少拆分为以下三类工厂。

#### `pileZone`

用于摸牌堆、武将牌堆、身份牌堆、备牌槽和需要真正重叠的牌堆：

```ts
alignChildren: true
preventPiles: false
stackOffsetX: 0
stackOffsetY: 0
```

#### `handZone`

用于玩家手牌：

```ts
alignChildren: true
preventPiles: true
childrenPerOwner: true
stackOffsetX: <可配置正值>
stackOffsetY: 0
```

只有手牌区使用横向展开和自动重排。

#### `freeZone`

用于私密展示区、对外展示区、待回收区以及确实需要 Holder 捕获的自由区域：

```ts
alignChildren: false
preventPiles: false
```

卡牌保留玩家放置位置，允许自由重叠和原生 Pile，不自动排成一列或一排。

普通公共桌面不强制使用 `freeZone`，避免形成覆盖整张桌布的大型拖放捕获区。

### 12. 区域视觉清晰化

当前大量区域表现为相似的白色矩形，区域用途和隐私等级不清晰。下一版建立统一但有区分度的视觉语言：

| 区域 | 推荐视觉语义 |
|---|---|
| 对外展示区 | 半透明绿色／木质底板、公开图标、实线边框 |
| 私密展示区 | 深色半透明底板、锁图标、斜纹或遮罩边框 |
| 手牌区 | 深色横向面板、手牌图标、本人视角强调 |
| 待回收区 | 灰蓝半透明底板、循环箭头、虚线边框 |
| 摸牌堆 | 接近卡牌尺寸、牌堆图标、数量提示 |
| 备牌托盘 | 暗红／铜色双边框、收纳图标 |
| 普通公共桌面 | 无框、保留桌布纹理 |
| 功能控制条 | 紧凑中性色面板，与游戏区域区分 |

共同要求：

- 不再以纯白底作为所有 Holder 的默认外观。
- 不能只依赖颜色，同时使用标题、图标或符号、边框样式和底纹区分。
- 区域标题放在边界内部或固定标题栏中，不得被卡牌完全遮住。
- 底板保持半透明、低干扰，卡牌仍是视觉主体。
- 同一玩家模块可共享座位强调色和编号。
- 空区域也能一眼识别用途；有牌时标题和归属信息仍可辨认。
- 所有文字与背景保持足够对比度。
- 测试常见 PC 分辨率、浏览器缩放和至少一种平板横屏尺寸。

视觉优化只改善识别和操作，不重新引入装备、判定等规则槽位，也不增加自动规则判断。

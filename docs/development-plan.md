## Phase 1.1：三分区解耦、真实牌堆与视觉清晰化（下一步）

### 1. 玩家结构改为三个独立区域

废止“武将、体力、装备、判定、附加牌”五类固定槽位，不再使用一个大型玩家父模块强制包裹全部组件。每个玩家只保留一个 Seat，以及三个通过 Seat 身份和权限逻辑关联、但空间上相互独立的区域：

1. **对内展示区**：身份牌、暗置武将、私密任务牌及其他长期私密信息。
2. **手牌区**：严格属于本座位玩家的私密手牌。
3. **对外展示区**：武将牌、体力牌或标记、装备、判定、附加牌、公开身份及其他公开状态。

三个区域分别拥有独立坐标、尺寸和旋转，不建立必须共同移动的父子布局关系；后续布局解锁时可以分别调整，锁定时统一禁止误拖。移动区域不得改变 Seat、卡牌所有者或私密可见性。

### 2. 对内展示区的隐私语义

对内展示区采用“物件存在公开、牌面内容私密”的模式：

- 卡牌进入对内展示区时默认恢复为背面。
- 所属玩家可以在区内翻面并查看真实正面。
- 其他玩家、观察者以及房主无论卡牌实际正反状态如何，始终只能看到牌背。
- 原生 `enlarge` 放大不得绕过该遮罩；非所属玩家放大时仍只能看到牌背。
- 卡牌离开对内展示区时，必须在私密保护仍有效的情况下先恢复为背面，再解除该区域的私密归属。
- 卡牌移入公共区域后继续保持背面；只有玩家在公共区域再次手动翻面，其他人才可看到正面。
- 禁止“离开私密区即自动公开正面”，也禁止先解除隐私再翻回背面造成瞬时泄漏。

身份公开的标准操作为：对内展示区取出身份牌 → 公共或对外展示区中仍保持背面 → 玩家手动翻面 → 全体可见。

### 3. 手牌区的独立职责

手牌区只处理手牌，不承担身份或长期私密展示：

- 所属玩家看到正面，其他玩家和观察者看不到正面。
- 使用 `childrenPerOwner` 或等效原生归属机制。
- 进入时按本座位玩家建立归属；离开后按公共卡牌状态显示。
- 手牌横向展开，手牌增加时允许压缩间距。
- 对外可选择显示手牌数量，但不得显示牌面内容。
- 玩家离座、换座和异常清理不得将原手牌错误转交给新入座玩家。

### 4. 对外展示区的自由摆放

对外展示区是公开状态空间，不再细分武将槽、体力槽、装备槽、判定槽或附加牌槽：

- 玩家可以自由摆放武将、体力、装备、判定、附加牌和公开标记。
- 区域不自动识别或校验卡牌类别。
- 卡牌不会被强制排成固定队列。
- 两张或多张卡牌可以按玩家意图重叠、堆叠或错位摆放。
- 区域本身不自动翻牌，也不改变任何规则状态。

### 5. Holder按用途拆分

删除当前“一种 `zone()` 适用于全部区域”的设计，至少拆分为以下三类工厂：

#### `pileZone`

用于主牌堆、武将牌堆、身份牌堆和弃牌堆：

```ts
alignChildren: true
preventPiles: false
stackOffsetX: 0
stackOffsetY: 0
```

要求卡牌能够在同一坐标真正重叠并形成VirtualTabletop原生Pile，不能再横向散开。牌数提示应通过数量标签或Pile显示实现，而不是通过错位展开表示。

#### `handZone`

用于玩家手牌：

```ts
alignChildren: true
preventPiles: true
childrenPerOwner: true
stackOffsetX: <可配置正值>
stackOffsetY: 0
```

只有手牌区使用横向展开和自动重排。

#### `freeZone`

用于对内展示区、对外展示区和中央出牌／结算区：

```ts
alignChildren: false
preventPiles: false
```

卡牌保留玩家放置位置，允许自由重叠和原生Pile，不自动排成一列或一排。

### 6. 区域视觉清晰化

当前大量区域仅表现为相似的白色矩形，区域用途和隐私等级不清晰。下一版必须建立统一但有区分度的桌面视觉语言：

- 不再以纯白底作为所有Holder的默认外观。
- 对内展示区、手牌区、对外展示区、牌堆区、弃牌区和结算区必须具有可辨认的视觉差异。
- 每个区域同时使用标题、图标或符号、边框样式和底色／纹理进行区分，不能只依赖颜色。
- 区域标题放在边界内部或固定标题栏中，不得被卡牌完全遮住，也不得悬出安全边界。
- 私密区域应有明确的锁或遮罩提示；对外展示区应表现为公开桌面空间；牌堆区应接近卡牌尺寸并带清楚的牌堆名称或数量提示。
- 底板使用半透明、低干扰材质，确保卡牌仍是视觉主体；避免高亮纯白大块区域压过桌布和卡面。
- 同一玩家的三个区域可共享座位强调色或编号，但仍须通过文字／图标明确具体功能。
- 空区域也必须能一眼识别用途；有牌时边框、标题和归属信息仍然可辨认。
- 所有文字与背景保持足够对比度，并测试常见PC分辨率及浏览器缩放。

视觉优化只改善识别和操作，不增加装备、判定等规则槽位，也不引入自动规则判断。

### 7. 自动与人工测试

新增或调整测试：

- [ ] 主牌堆、武将牌堆和弃牌堆允许原生Pile，初始卡牌不散开
- [ ] 只有手牌区存在非零排列偏移
- [ ] `pileZone`不得设置`preventPiles: true`
- [ ] `freeZone`不得强制自动排列子卡牌
- [ ] 三个玩家区域不依赖同一大型父模块
- [ ] 对内展示区中本人可翻面查看，其他玩家始终只能看到牌背
- [ ] 对内卡牌离开时先恢复背面，再解除私密保护
- [ ] 卡牌移到公共区后保持背面，必须再次手动翻面才公开
- [ ] `enlarge`、观察者和房主均不能绕过对内区或手牌区隐私
- [ ] 手牌离座、换座和重新入座时不会错误转移归属
- [ ] 区域标题、图标、边框和底板在空区与有牌状态下均可辨认
- [ ] 四个玩家的三类区域、中央区和牌堆区无严重越界或重叠
- [ ] 多浏览器同步过程中不存在短暂正面泄漏

### 8. Phase 1.1验收标准

- 初始主牌堆与武将牌堆在视觉和交互上是真正的一叠牌。
- 每位玩家只保留对内展示区、手牌区、对外展示区三个功能区域。
- 玩家可以用对外展示区自由表达武将、体力、装备、判定和附加牌状态。
- 对内展示区满足“本人可看正面、他人永远只见牌背、移出后仍需再次翻面才公开”。
- 手牌和对内展示的大图功能无隐私泄漏。
- 各区域不再是含义不明的统一白色矩形，玩家无需阅读说明即可大致判断区域用途和隐私等级。
- 4人桌面在常见PC分辨率下无严重越界、重叠或不可操作区域。
- 构建、校验和自动测试全部通过，并完成至少两个不同玩家会话的人工验证。

Phase 1.1通过前，不制作5–10人版本，不接入完整正式牌组，也不增加自动规则。

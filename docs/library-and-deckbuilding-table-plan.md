# 牌库与编组桌开发计划

> 适用分支：`refactor/native-vtt-4p-prototype`  
> 项目原则：弱规则、弱状态、强同步、强可见性控制。  
> 本计划描述与主游戏桌共存的牌库与编组区域，以及超大连续桌布、主要组件缩放、牌库浏览、牌堆编组、归位和隐私边界。

## 1. 背景与目标

主桌边缘的备牌托盘只适合存放少量备用牌或完整牌堆。当武将牌、身份牌和扩展牌数量增加后，会出现：

- 无法快速浏览武将正面；
- 难以按扩展包分类和筛选；
- 不便比较并选择本轮使用的武将；
- 身份牌构成不容易人工核对；
- 收拢、盖回、洗牌和送入主桌流程繁琐；
- 准备阶段组件挤占主游戏桌；
- 固定尺寸模块难以适配超大桌布和不同玩家人数。

因此新增 **牌库与编组桌区域**，并让主要布局组件支持受控缩放，形成以下人工流程：

```text
浏览牌库
→ 选择候选牌
→ 排除或暂存
→ 核对本局构成
→ 收拢、盖回和洗牌
→ 送入主游戏桌
```

牌库桌和组件缩放都不执行三国杀规则判断，不自动决定武将数量、身份构成、扩展组合或胜负状态。

## 2. 核心架构：同房间、同画布、双桌并排

在同一个 `.vtt` 房间和同一块超大有限桌布上，将主游戏桌与牌库编组桌左右并排放置：

```text
同一块连续桌布
├── 左侧：主游戏桌
├── 中间：过渡与方向提示区
└── 右侧：牌库与编组桌
```

两张桌共用同一批真实卡牌对象和共享游戏状态，但占据不同空间。每位玩家独立缩放和平移自己的镜头，因此一名玩家可以留在主桌，另一名玩家可以查看牌库桌，不强制同步镜头。

本方案是“实用上接近无限”的超大有限桌面，不实现真正无限坐标，不使用负坐标，也不修改 VirtualTabletop 核心源码。

### 2.1 Board尺寸

首版建议：

```json
{
  "_meta": {
    "gameSettings": {
      "boardSize": {
        "width": 3600,
        "height": 1400
      }
    }
  }
}
```

人工验收可在以下范围调整：

```text
宽度：3200–4200
高度：1300–1800
```

一般不建议超过约 `5000 × 2500`，不得默认使用 `10000 × 10000`，避免初始视图过度缩小、导航困难、移动端体验恶化和卡牌遗失。

### 2.2 推荐空间划分

以 `3600 × 1400` 为基准：

```text
安全外边距：约60–80 px
主游戏桌：x=80–1760，y=80–1320
过渡走廊：x=1760–1900
牌库桌：x=1900–3520，y=80–1320
```

坐标由统一布局配置管理，不允许在多个组件文件中重复硬编码。

过渡走廊不放牌堆和玩家模块，只放低干扰方向提示：

```text
← 主游戏桌    牌库与编组桌 →
```

### 2.3 独立视图与降级

- 两张桌默认同时存在于同一Board。
- 玩家之间不强制同步缩放和平移位置。
- 最终牌堆通过明确Routine送入主桌，不要求长距离手拖整叠牌。
- 对局开始后可锁定牌库桌编辑，但仍允许查看。
- 移动端或低性能设备可隐藏牌库桌装饰与浏览网格。
- 降级仅影响显示，不删除、复制或改变真实卡牌状态。

## 3. 连续桌布与导航

整块Board使用可无缝重复的低干扰毛毡、木纹或暗色纹理：

- 背景覆盖完整Board；
- 不绘制明显的最外层厚边框；
- 不使用暴露画布终点的强烈装饰；
- 背景纹理不得影响卡牌识别；
- 极端边缘使用很淡的安全警示带。

主桌与牌库桌保持统一风格，但通过轻量桌垫区分：

- 主桌：深绿或木质主桌垫；
- 牌库桌：灰绿、蓝绿或铜色编组桌垫；
- 不使用大面积纯白区域；
- 各桌顶部有清楚的大标题；
- 中间有方向提示和可选区域图例；
- “送入主桌”“返回牌库”按钮含义明确。

若纯 `.vtt` 无法控制当前客户端镜头，则不伪造镜头跳转，依赖原生缩放和平移以及清晰的导航标识。

## 4. 主要组件缩放

### 4.1 目标与基本规则

组件本体缩放与玩家镜头缩放必须分开：

- **镜头缩放**：仅影响当前客户端视图，不改变共享状态。
- **组件缩放**：修改Widget的原生 `scale`，所有玩家看到相同尺寸。

组件缩放用于提高超大桌布的空间利用率和多人布局适配能力，不用于隐藏牌、规避交互或改变规则。

### 4.2 支持缩放的主要组件

首版允许以下组件整体缩放：

- 玩家模块根节点；
- 武将牌库浏览面板；
- 本局候选展示面板；
- 备牌托盘；
- 身份构成区；
- 待回收／待洗牌区；
- 其他明确标记为布局组件的准备区。

推荐离散比例：

```text
紧凑：75%
较小：90%
标准：100%
较大：115%
```

连续任意比例和自由拖拽缩放手柄不作为首版目标，避免产生难以复现的零散比例。

### 4.3 不允许或严格限制缩放的对象

以下对象原则上保持标准尺寸：

- 单张普通游戏牌；
- 主摸牌堆和最终牌堆；
- 单张身份牌或武将牌本体；
- 手牌中的单张卡牌；
- 关键确认按钮和顶部控制条。

手牌过多时优先调整排列间距、Holder宽度或行数，不通过大幅缩小卡牌解决。

### 4.4 父组件缩放

玩家模块、牌库浏览区和备牌托盘应设置单一缩放根节点：

```text
可缩放根节点
├── 标题栏
├── 区域底板
├── Holder
├── 标签和图标
└── 内部卡牌
```

只修改根节点 `scale`，内部元素随父节点统一缩放。每条组件层级最多设置一个主要缩放节点，禁止桌面父层、区域父层和卡牌本体多层重复缩放，避免比例相乘。

### 4.5 缩放锚点

可缩放模块统一使用左上角锚点：

```css
transform-origin: top left;
```

这样模块的 `x`、`y` 保持稳定，视觉尺寸按右下方向变化，便于自动排列、碰撞和边界计算。

### 4.6 权限和交互

- 布局锁定时不得改变组件缩放。
- 布局解锁后显示缩放菜单或 `− / +` 控件。
- 普通玩家只能调整自己的玩家模块。
- 房主或拥有编组权限的玩家可调整牌库面板和备牌托盘。
- 缩放结果属于共享状态，所有玩家同步可见。
- 必须提供“恢复默认尺寸”。
- 危险或大范围统一调整应有明确提示。

推荐菜单：

```text
组件尺寸
├── 紧凑 75%
├── 较小 90%
├── 标准 100%
├── 较大 115%
└── 恢复默认
```

### 4.7 缩放感知布局

项目自己的布局、碰撞和边界算法必须考虑 `scale`。无旋转时：

```ts
visualWidth = width * scale;
visualHeight = height * scale;
right = x + visualWidth;
bottom = y + visualHeight;
```

仅允许 `0° / 90° / 180° / 270°` 旋转时，`90°`和`270°`交换视觉宽高。首版不开放任意角度旋转的可缩放模块。

自动整理应：

1. 优先尝试100%；
2. 检查桌面边界、中央区域和相邻模块碰撞；
3. 空间不足时降到90%；
4. 仍不足时降到75%；
5. 不在无必要时强制放大或缩小；
6. 允许之后人工调整。

推荐参考：

```text
4人：100%或115%
5–6人：100%
7–8人：90%
9–10人：75%
```

人数仅作为初始建议，最终由空间检测决定。

### 4.8 拖出缩放区域

真实卡牌从75%的牌库浏览面板拖到100%的候选区时，视觉尺寸可以恢复为标准大小。必须测试：

- 拖动过程中的视觉跳变；
- Drop Shadow位置；
- 父子坐标换算；
- Pile合并；
- 放大功能；
- 从缩放区域返回原牌库。

缩放不得改变卡牌真实身份、来源元数据、正反面和隐私权限。

## 5. 牌库桌总体布局

```text
┌────────────────────────────────────────────────────────┐
│ 武将库｜身份库｜游戏牌库｜扩展管理｜锁定｜重置编组桌     │
├────────────┬──────────────────────┬────────────────────┤
│ 分类／扩展栏 │ 牌库浏览与分页展示区   │ 本局候选区           │
├────────────┴──────────────────────┼────────────────────┤
│ 身份供应与本局身份构成区            │ 最终牌堆生成／送出区   │
├───────────────────────────────────┴────────────────────┤
│ 排除区｜暂存区｜返回原牌库区｜状态与数量提示             │
└────────────────────────────────────────────────────────┘
```

牌库桌保留足够自由操作空间，不用大量Holder铺满桌垫。区域同时使用标题、图标、边框和半透明底色区分，不能只依赖颜色。

## 6. 武将牌库浏览

首版至少按扩展包分类：标准、风、火、林、山、一将成名、SP和其他已接入扩展。

每页推荐展示20–30张正面武将牌，例如 `5×4` 或 `6×4` 网格。支持：

- 正面浏览；
- 悬停或长按放大；
- 拖入候选区、排除区或暂存区；
- 返回所属扩展；
- 显示已选择、已排除和仍在牌库的状态；
- 上一页、下一页、当前页码、扩展总数和候选数量。

浏览网格不得形成Pile，也不得复制卡牌。未展示的真实卡牌进入隐藏牌库Holder或通过显示状态控制。

## 7. 候选区与最终武将牌堆

候选区用于核对本轮武将：

- 候选牌保持正面；
- 可自由排列、比较和放大；
- 可移除、排除或暂存；
- 显示实时数量；
- 不自动决定本局应选多少张。

生成最终武将牌堆时：

1. 只收集候选区的武将牌；
2. 在候选区内统一恢复背面；
3. 收拢为真正的VirtualTabletop原生Pile；
4. 根据用户操作决定是否洗牌；
5. 放入最终武将牌堆Holder；
6. 更新数量和状态。

不得收集牌库浏览区、排除区、暂存区、主桌或其他牌库中的牌。

“送入主桌”必须移动同一个真实Pile，不复制、不自动抽取、不改变牌序，并防止重复点击生成重复牌堆。

## 8. 身份牌供应与构成

身份牌采用“供应堆＋本局构成区”：

```text
主公
忠臣
反贼
内奸
其他模式身份
```

玩家人工取出所需数量并核对构成。系统不判断人数规则。

“盖回并洗牌”执行：

1. 只收集身份构成区；
2. 统一恢复背面；
3. 收拢为Pile；
4. 洗牌；
5. 移入最终身份牌堆；
6. 允许送入主桌。

身份牌分发后，牌库桌、房主权限、放大和缩放功能都不得绕过隐私。

## 9. 排除、暂存、来源和唯一性

排除区和暂存区都不参与最终牌堆生成。返回原牌库时根据来源归位，不要求用户长距离拖动。

每张可编组卡牌建议保存：

```ts
libraryType: 'general' | 'identity' | 'playing' | 'token'
sourcePack: string
homeZone: string
poolState: 'library' | 'candidate' | 'excluded' | 'staging' | 'final' | 'active'
```

不得默认克隆卡牌。每张实体牌在同一时刻只存在一份。缩放、分页、隐藏和送入主桌都不得产生重复对象。

## 10. 完整牌库浏览器

牌量很大时可增加本地 `INPUT choose` 浏览器，用于快速浏览和选择。

要求：

- 弹层仅当前操作者可见；
- 不在共享桌面同步创建大型菜单；
- 不克隆实体牌；
- 已在候选、排除或主桌中的牌显示状态或禁止重复选择；
- 浏览器只是效率工具，不能替代实体候选区和最终牌堆核对。

## 11. 权限与隐私

默认所有玩家可以查看公开牌库、放大公开牌以及查看候选和排除状态。

提供：

```text
共同编组：所有已入座玩家可添加或移除候选牌
房主编组：普通玩家只读，房主负责修改候选牌
```

房主可锁定牌库桌、生成牌堆、洗牌、送入主桌、重置和恢复异常归位，但不得查看玩家手牌、已分发身份或绕过私密展示区。

## 12. 重置、归位和防遗失

至少提供：

- **清空候选**：候选、排除和暂存牌返回原牌库；
- **重置牌库桌**：恢复尚未送入主桌的牌库卡牌和区域；
- **完整恢复初始状态**：同时影响主桌和牌库桌，必须二次确认；
- **检查异常卡牌**：列出或高亮脱离已知区域的牌。

要求：

- 所有功能区域位于安全边距内；
- 卡牌不得越出Board有效范围；
- 靠近极端边缘时提供低调警示；
- 使用 `homeZone` 和 `poolState` 判断归属；
- 不自动回收主桌上正常使用的自由卡牌；
- 不静默复制、删除或丢失卡牌。

## 13. Holder与洗牌边界

- 主桌摸牌堆、武将牌堆和最终身份牌堆使用真正的 `pileZone`。
- 牌库浏览网格不得形成Pile。
- 候选、排除和暂存区采用自由或明确排列区域。
- 主桌待回收区只处理主桌待回收牌。
- 牌库生成只处理对应候选区。
- 主桌洗牌不得收集牌库桌、过渡走廊或备牌托盘中的牌。
- 牌库桌重置不得处理玩家手牌、私密展示区或主桌活动牌。

建议新增：


自动测试至少验证：

- Board尺寸和边界有效；
- 连续背景覆盖完整Board；
- 主桌、过渡区和牌库桌不重叠；
- 组件缩放值只能来自允许列表；
- 布局锁定时不能缩放；
- 普通玩家不能缩放其他玩家模块；
- 碰撞和越界判断使用视觉尺寸；
- 缩放后Holder拖放和父子坐标正确；
- 卡牌在牌库、候选、最终牌堆和主桌之间保持唯一；
- 洗牌范围严格隔离；
- 隐私牌不会因为缩放、拖放或牌库操作泄漏。

人工测试至少验证：

- 两个浏览器会话可分别停留在主桌和牌库桌；
- 一个玩家的镜头缩放不改变其他玩家镜头；
- 组件本体缩放能同步到所有玩家；
- 75%、90%、100%和115%下标题和按钮仍可读；
- 缩放模块中的卡牌可以可靠拖出和放回；
- 触屏操作不会频繁误触缩放或拖动；
- 自动整理在不同人数和比例下无严重碰撞；
- 放大功能与隐私限制保持正确。

## 17. 验收标准

完成时必须满足：

- 主桌与牌库桌位于同一连续Board并可独立浏览；
- Board尺寸适中，不依赖真正无限坐标；
- 两个玩家可分别查看不同桌区，互不强制同步镜头；
- 玩家模块、牌库浏览区和备牌托盘支持受控离散缩放；
- 组件缩放属于共享布局状态，权限和锁定逻辑正确；
- 缩放后的视觉边界、碰撞、拖放和自动整理可靠；
- 普通卡牌和核心牌堆保持标准尺寸；
- 武将牌可按扩展分页浏览、选择、排除、暂存和比较；
- 候选区可生成真正背面重叠的武将Pile；
- 最终牌堆作为同一真实对象送入主桌；
- 身份牌可人工构成、盖回、洗牌和送入主桌；
- 不存在重复实体牌；
- 主桌与牌库桌洗牌范围完全隔离；
- 房主和普通玩家都不能绕过手牌或身份隐私；
- 重置不会丢牌、复制牌或误处理活动牌；
- 常见PC分辨率和移动端降级模式可用；
- 构建、验证和自动测试通过；
- 至少两个不同玩家会话完成导航、缩放、选择、生成、送入和隐私测试。

## 18. 当前边界

本计划不包含：

- 真正无限坐标、动态扩展画布或负坐标；
- 修改VirtualTabletop上游源码；
- 连续任意比例组件缩放；
- 单张卡牌自由缩放；
- 任意角度旋转的可缩放模块；
- 自动判断三国杀人数规则；
- 自动决定身份构成；
- 自动推荐、平衡或禁用武将；
- 技能、距离、体力、伤害、回合或胜负判定；
- 通过房主权限查看私密牌；
- 默认克隆完整牌库。

牌库桌负责清晰、安全、可恢复的人工牌库浏览与编组；超大桌布负责提供空间和独立视图；组件缩放负责提高布局适配能力。三者都不得改变游戏规则和隐私边界。

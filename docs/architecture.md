# 4 人 Phase 1.1 架构

源码分为 `data`（牌面目录与 Deck）、`layouts`（纯坐标）、`widgets`（区域工厂与玩家模块）、`routines`（少量桌面操作）、`variants`、`types` 和 `validation`。TypeScript 在构建时生成 `0.json`，不直接维护巨型 JSON。

## 桌面结构

- 玩家模块仅包含标题／Seat、对外展示区和私密展示区；模块背景是拖动把手，卡牌区不会拖动父模块。
- 对外展示区是自由 Holder，不区分武将、体力、装备、判定和附加牌槽位。
- 四名玩家共用世界坐标底部的个人手牌条，这是不修改上游源码情况下的原生降级方案。`childrenPerOwner` 让每个客户端只布局自己的牌，模块上公开显示手牌数量。
- 摸牌堆、待回收区、普通公共桌面和备牌托盘彼此独立。常规洗牌只从待回收区移动卡牌到摸牌堆。
- 玩家 1 的 Seat 是轻量布局管理位，只能看到布局工具，不能因此看到其他人的手牌或私密展示。

## 隐私顺序

私密区进入属性先把牌恢复到背面，再附加对应 Seat 可见性；离开属性按 `activeFace → onlyVisibleForSeat → owner` 顺序先翻回背面，再解除隐私和所有者。拖动过程中 VirtualTabletop 继承目标 Holder 的 Seat 可见性。其他玩家和观察者只看到公开私密区底板。

手牌本身不永久携带 Seat 可见性，离开手牌后恢复为公共物件。玩家离座或换座时，旧牌仍保留原玩家 `owner`，不会自动转交给新入座玩家。

盲选使用纯牌背代理，不复制或展示真实手牌。目标玩家手动摆放等量代理，操作者指出位置，再由目标玩家人工交牌。

## 牌面与打包

`pnpm assets` 只读加载参考包的 552 张去框 PNG，以最长边不超过 480 像素、WebP 质量 82 生成缓存，再计算与 VirtualTabletop 服务器一致的 CRC32／文件长度 URL。相同牌面按内容哈希复用；`.vtt` 内包含 `0.json` 和 482 个唯一 `assets/*.webp`。

所有真实牌面通过 Deck `faceTemplates/cardTypes` 接入，牌背使用项目生成的非空原生牌背。卡牌、武将和身份统一使用原生 `enlarge`，不修改客户端悬停、长按或屏幕边界逻辑。
